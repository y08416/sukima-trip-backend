# 最近スポット表示機能 UIアプローチ比較

## 前提・背景

現在のバックエンドは `GET /spots?lat=&lng=` でスポット一覧を `distance_km` 付きで返している。  
最近スポットの特定はフロントが `distance_km` でソートすれば実現可能。  
矢印を向けるには現在レスポンスに含まれていない **bearing（方位角: 0〜360°）** が追加で必要。

---

## 案A: フッターに矢印を常時表示

### 概要

画面下部のフッターエリアに「最近スポット名・距離・方向矢印」を常時固定表示する。

```
┌─────────────────────────────┐
│                             │
│         マップ画面           │
│                             │
├─────────────────────────────┤
│  ↗  金閣寺  0.8km           │  ← フッターに常時表示
└─────────────────────────────┘
```

### UX 評価

| 項目 | 評価 | 理由 |
|------|------|------|
| 発見しやすさ | ◎ | 常時表示のため見落としがない |
| 邪魔さ | △ | フッターの一部を常に占有する |
| 操作感 | ◎ | タップでスポット詳細に遷移できる |
| 歩行中の視認性 | ◎ | 固定位置なので慣れやすい |

### 実装コスト

- **フロント**: 低〜中
  - フッターコンポーネントに追加
  - `DeviceOrientationEvent` でデバイス向きを取得し矢印を回転
- **バックエンド**: 低
  - `GET /spots/nearest` を新設（bearing 付きで最近スポット1件を返す）
  - または `GET /spots` のレスポンスに `bearing` フィールドを追加

### バックエンド変更例

```
GET /spots/nearest?lat=35.0&lng=135.0

Response:
{
  "place_id": "ChIJxxx",
  "name": "金閣寺",
  "distance_km": 0.8,
  "bearing": 42.3
}
```

### メリット

- ユーザーが意識しなくても常に「次どこへ行くか」が分かる
- マップが不要な局面でも機能する
- モバイルの標準的なナビUIに近く学習コスト低

### デメリット

- フッターの高さが増え、マップ表示領域が若干狭まる
- スポットが近距離に存在しない場合の表示制御が必要（例: 5km以上なら非表示）

## 案B: 看板（カード）を表示

### 概要

マップ上またはスポットアイコンに看板スタイルのカード/バルーンをオーバーレイ表示する。AR風または地図吹き出し形式。

```
┌─────────────────────────────┐
│                             │
│     ┌──────────────┐        │
│     │ ↗ 金閣寺     │        │
│     │   0.8km      │        │
│     └──────┬───────┘        │
│            ▼                │
│          [●] スポット        │
└─────────────────────────────┘
```

### UX 評価

| 項目 | 評価 | 理由 |
|------|------|------|
| 発見しやすさ | ○ | マップ上で視覚的に目立つ |
| 邪魔さ | △ | マップの他の要素を隠す可能性 |
| 操作感 | ○ | 看板タップで詳細確認 |
| 情報量 | ◎ | 名前・距離・写真なども載せられる |

### 実装コスト

- **フロント**: 高
  - マップライブラリへの Custom Overlay 実装が必要
  - スポットアイコンとの位置合わせ制御
  - 複数スポット時の重なり制御
- **バックエンド**: 低〜中
  - 既存の `GET /spots` レスポンスで対応可能
  - bearing を追加する場合は `GET /spots/nearest` を新設

### バックエンド変更例

```
既存 GET /spots?lat=&lng= のレスポンスに bearing を追加:

[
  {
    "place_id": "ChIJxxx",
    "name": "金閣寺",
    "lat": 35.039,
    "lng": 135.729,
    "distance_km": 0.8,
    "bearing": 42.3   ← 追加
  },
  ...
]
```

### メリット

- 地図上でスポットの位置と一体化した表示でコンテキストが明確
- 将来的に写真やレビュー数など情報を拡張しやすい
- ゲーム的・観光アプリ的なビジュアルに合う

### デメリット

- マップ画面前提の設計になる
- 実装が最も重く、マップライブラリに強く依存
- 複数スポットが近い場合に看板が重なるUI制御が複雑

## 案C: ホバー（タップ）で矢印を表示

### 概要

スポットアイコンや特定のUIボタンをタップ/ホバーしたときだけ矢印が出現する。普段は非表示。

```
通常時:
┌─────────────────────────────┐
│                             │
│   [●] [●]   [●]            │  ← スポットアイコンのみ
│                             │
└─────────────────────────────┘

タップ後:
┌─────────────────────────────┐
│                             │
│   [●] [●]  ↗[●]            │  ← タップしたスポットに矢印
│                             │
└─────────────────────────────┘
```

### UX 評価

| 項目 | 評価 | 理由 |
|------|------|------|
| 発見しやすさ | △ | ユーザーが能動的に操作しないと出ない |
| 邪魔さ | ◎ | 普段は非表示でクリーンなUI |
| 操作感 | △ | 「タップすると矢印が出る」と知らないと使われない |
| 歩行中の視認性 | △ | 都度タップが必要で歩きながら使いにくい |

### 実装コスト

- **フロント**: 中
  - タップイベントのハンドリング
  - トグル式の矢印アニメーション
- **バックエンド**: 最小
  - 既存 `GET /spots` で lat/lng は返っているため追加変更なし
  - フロントで bearing を計算することも可能

### フロント側 bearing 計算（バックエンド変更不要の場合）

```javascript
function calcBearing(userLat, userLng, spotLat, spotLng) {
  const dLng = (spotLng - userLng) * Math.PI / 180;
  const lat1 = userLat * Math.PI / 180;
  const lat2 = spotLat * Math.PI / 180;
  const y = Math.sin(dLng) * Math.cos(lat2);
  const x = Math.cos(lat1) * Math.sin(lat2) - Math.sin(lat1) * Math.cos(lat2) * Math.cos(dLng);
  return (Math.atan2(y, x) * 180 / Math.PI + 360) % 360;
}
```

### メリット

- バックエンド変更ゼロで着手できる
- マップUIがスッキリ保てる
- 他のスポットを確認しながら任意のスポットへの方向を調べられる

### デメリット

- 機能の存在に気づきにくく使われない可能性が高い
- 「最近スポットへ誘導する」という目的には受動的すぎる

## 推奨案と理由

### 推奨: **案A（フッター常時表示）**

**理由:**
1. 「すきま時間に観光スポットへ誘導する」というアプリの目的に最も直結する
2. ユーザーが意識しなくても常に次の行き先が示されるため、使われやすい
3. 実装コストが最も低く、バックエンド変更も `GET /spots/nearest` 1エンドポイントの追加のみ
4. スマホの標準的なナビUIに近く、学習コストが低い

### 段階的実装プラン

| フェーズ | 内容 | 工数目安 |
|---------|------|---------|
| Phase 1 | バックエンド: `GET /spots/nearest` 追加（bearing 付き） | 0.5日 |
| Phase 2 | フロント: フッターに距離・名前を表示（矢印なし） | 1日 |
| Phase 3 | フロント: デバイス方位センサーと連動した矢印回転 | 1〜2日 |

Phase 2 まで完成させて反響を見てから Phase 3 に進む段階的アプローチも有効。

`internal/repository/spot.go` に `CalcBearing` 関数を追加:

```go
func CalcBearing(lat1, lng1, lat2, lng2 float64) float64 {
    dLng := (lng2 - lng1) * math.Pi / 180
    lat1R := lat1 * math.Pi / 180
    lat2R := lat2 * math.Pi / 180
    y := math.Sin(dLng) * math.Cos(lat2R)
    x := math.Cos(lat1R)*math.Sin(lat2R) - math.Sin(lat1R)*math.Cos(lat2R)*math.Cos(dLng)
    bearing := math.Atan2(y, x) * 180 / math.Pi
    return math.Mod(bearing+360, 360)
}
```
